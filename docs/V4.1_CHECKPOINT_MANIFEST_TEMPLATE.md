# v4.1 Reproducible Checkpoint Manifest

Every sprint checkpoint records actual source and evidence. A later source state must never be relabeled as an earlier checkpoint.

## Required fields

- Sprint ID
- Completion timestamp (UTC)
- Git commit SHA
- Source tree SHA-256 manifest reference
- Protected asset SHA-256 values
- Package version
- Database migration set
- Focused test command and result
- Normalized regression command and result
- Visual evidence paths when the sprint changes a visual flow
- Known limitations introduced, resolved, or unchanged
- External activation dependencies
- Release-gate package names and SHA-256 values when applicable

## Status vocabulary

- `PASS`: the stated command or review ran successfully with preserved evidence.
- `FAIL`: it ran and did not meet the gate.
- `BLOCKED-EXTERNAL`: a named environment, credential, physical device, or authorization was unavailable after local work was exhausted.
- `NOT-APPLICABLE`: the sprint did not change or require that gate; include the reason.

`NOT-RUN` is not a passing status. Historical entries are append-only.
