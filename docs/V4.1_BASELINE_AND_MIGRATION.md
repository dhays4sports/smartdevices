## SD41-FND-0.2 architecture delta

Decision: v4.1 remains additive within the existing architecture.

| Boundary | v4.0 | v4.1 delta |
|---|---|---|
| Journey | Ad hoc explorer component state | Typed reducer with allow-listed states and recovery |
| Scan | Domain + concern only | Versioned question content and deterministic branching |
| Matching | Concern membership + subscription sort | Pure rules returning priority, rationale, assumptions, unknowns, exclusions |
| Scene | Raster image, hotspots, three text stages | Reusable scene controller plus functional overlays and text-equivalent controls |
| Motion | Decorative progress line | Interruptible causal demonstration state machine |
| Results | Product card grid | Protection area → solution class → device option relationship view plus ordered list |
| Plan | Schema v1, one concern | Backward-compatible v2 provenance with selected concerns, rationale, assumptions, unknowns |
| Events | None | Vendor-neutral, PII-free event interface with disabled and test adapters |
| Pro | Concern/device builder | Scan-aware provenance and v2 plan creation |
| Handoff | Schema v1 concern/device context | Backward-compatible schema v2 with non-sensitive scan provenance and explicit client intent |

### Module boundaries

- `app/lib/experience.ts`: journey states and event dictionary.
- `app/lib/scan.ts`: scan types, validation, branching, deterministic result rules.
- `content/scan-questions.json`: versioned editorial question definitions.
- `app/components/ProtectionExperience.tsx`: entry, scene, scan, results, and plan selection orchestration.
- `app/components/CausalDemo.tsx`: reusable demonstration controller.
- `app/components/DeviceUniverse.tsx`: relationship view and accessible ordered list.
- `app/lib/plan.ts`: v1 read compatibility and v2 creation/export provenance.
- Existing API, database, authorization, rate-limit, and integration modules remain authoritative at their current boundaries.

### Durable-state decision

D1 remains the authoritative hosted store. v4.1 adds append-only scan session/response tables and optional plan provenance columns so an activated hosted environment can resume consented context. Anonymous local mode stores only a non-authoritative, non-sensitive draft on the current device and labels it accordingly. Raw scan responses and PII are never serialized into share URLs.

### Backward compatibility

- Existing v1 URLs containing only domain, concern, and device IDs remain readable.
- Existing hosted plan rows default to schema version 1 and null v2 provenance.
- Plan v2 uses the same opaque hosted IDs and write capabilities.
- Handoff schema v1 remains accepted while v2 is introduced.
- Applied migrations remain immutable; v4.1 uses a new migration.
