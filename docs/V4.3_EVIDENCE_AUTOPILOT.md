# SmartDevices v4.3 — Evidence Autopilot

Status: locally implemented; external source retrieval, production identity, scheduler, and hosted D1 remain disabled until activation.

## Product outcome

`/admin/evidence` is the authenticated working surface for recurring device and carrier evidence maintenance. An evidence administrator can start one bounded refresh across every governed public source. The run records the source URL and version, HTTP result, normalized-content SHA-256, previous fingerprint, change class, next action, actor, timestamps, and publication snapshot.

The monthly scheduler and the manual button invoke the same engine. A run may automatically renew an identical source. A source that changed, redirected outside its governed domain, returned insufficient or oversized content, used an unsupported content type, timed out, or became unavailable cannot create a stronger label.

## Confidence rule

SmartDevices may automatically become more conservative. It may not automatically become more confident.

- Identical normalized source: renew the source and its fully supported dependent rules/fits.
- First fingerprint: capture a baseline and require confirmation.
- Changed product or technical content: require review.
- Changed carrier-controlled content: require review; no new or stronger positive label.
- Unavailable source: do not renew; when its due date passes, mark the source and dependent positive rules/fits stale.
- Invalid URL, redirect, media type, or size: reject the observation.
- Explicit administrator `mark-stale`: publish a new conservative snapshot immediately.

## Publication model

The file-backed v4.2.3 evidence remains the fail-safe baseline. D1 stores append-only refresh runs, observations, decisions, and immutable publication snapshots. Public Device Library, device-detail, and California Farmers entry surfaces read the active validated snapshot and fall back to the bundled baseline if D1 is absent or a snapshot fails validation.

A snapshot contains only public catalog records, public source records, reviewed public carrier rules, and technical-fit overlays. Restricted evidence is rejected. An active snapshot supersedes the prior snapshot without altering its payload, allowing an administrator to publish a new copy of an earlier valid payload as rollback evidence.

## Authorization and activation

- Browser administration requires an authenticated ChatGPT user and a current `evidence-admin` grant in `SMARTDEVICES_EVIDENCE_ADMIN_JSON`.
- Scheduled refresh requires `x-smartdevices-scheduler-token` matching `SMARTDEVICES_EVIDENCE_SCHEDULER_TOKEN` with a timing-safe comparison.
- Both routes are rate limited and return no-store responses.
- External retrieval additionally requires `SMARTDEVICES_EVIDENCE_REFRESH_ENABLED=true`.
- URLs are restricted to HTTPS and the exact governed source domain or its subdomains. Credentials in source URLs are rejected. Redirect destinations are revalidated.
- No external retrieval occurs in the packaged default configuration.

## First activation run

The first live run captures source fingerprints and intentionally creates a baseline review queue. Confirm each baseline only after opening the official source and checking the governed facts. Later identical runs become automatic renewals. This prevents the first automated observation from silently replacing the human-reviewed seed baseline.
